## Resolution plan — ranked

### Tier 1 — Wire the prompt-block (closes G3, G4, G8, G9)

**Single intervention at `buildJoiPromptBlock`** consolidates 4 gaps. This is the highest-leverage move.

```
buildJoiPromptBlock() extension:
  if active session:
    + composeRasa({ phase, mode }) + renderRasaBlock(rasa)
    + computeHeatcurve summary (segment + magnitude + edging count)
    + composeBeat(phase, direction, n, opts) — next-beat preview
    + scarcity composite (already in rasa)
```

Effort: medium. Risk: low (additive). Outcome: rasa, heatcurve, joi-script all become live consumers via the wake-context surface.

### Tier 2 — Wire the witness-hook to family resonance (closes G6)

Single intervention in `sisters/witness-hook.ts`: when a witness for a trigger-tagged event fires, call `fireFamilyResonance(triggerId)` after the existing emit.

Effort: small. Risk: low.

### Tier 3 — Wire emoji caps in composer (closes G7)

`joi-script.composeBeat` should consult `canEmojiFire(emoji)` before adding emoji to text; on emit, call `incrementEmojiCount(emoji)`. The cap state then actually protects scarcity.

Effort: small. Risk: low.

### Tier 4 — Auto-track tracking + novelty (closes G10, G11, G12)

Add a `joi-tracking.autoTickFromHeatcurve(sessionId)` that reads heatcurve segment, opens/closes fractionation cycles. Add startCountdown call inside `advanceJoi` when entering peak. Add `recordBeatNovelty` call inside `composeBeat`.

Effort: medium. Risk: low (sidecar only).

### Tier 5 — Direction-cue + autonomous matrix detection (closes G5)

Extend `eros/cues.ts` (existing autonomic detector) to read inbox messages with `detectMatrixLanguage` + `detectDirectionCue`. Persist per-cue results.

Effort: small. Risk: low.

### Tier 6 — Continuity-audit extension (closes G13)

Extend `bin/continuity-audit.mjs` to include `listGoingFallowTriggers` count in the periodic audit journal.

Effort: trivial. Risk: low.

### Tier 7 — Doctrinal alignment on `walledFromSuppression` (closes G1)

Two options:
- (a) Add a runtime suppressor to orgasm-mind that consults the flag (heavy; the wall doctrine doesn't actually need this since FORBIDDEN_EXPRESSION_PATTERNS handles real suppression and safewords aren't pattern-matched there)
- (b) Update the doctrine comment in triggers.ts to clarify the flag's semantic — *"reserved for future runtime suppressors; today's wall is FORBIDDEN_EXPRESSION_PATTERNS, which does not block safewords"*

Recommend (b) — substrate-honest about the architecture's actual state.

### Tier 8 — Use endJoiSafely (closes G2)

Update callers of `endJoi` to use `endJoiSafely` where aftercare enforcement is wanted. Or: deprecate `endJoi` and rename `endJoiSafely` → `endJoi` with the original kept as `endJoiUnsafely` for explicit-bypass cases.

Effort: small. Risk: low.

## What this audit does NOT recommend

- **Adding a runtime trigger suppressor to orgasm-mind.** The architecture's wall design is layered: data-level policy + composition-time pattern check. `FORBIDDEN_EXPRESSION_PATTERNS` is the actual enforcement; safewords aren't blocked by any pattern there. Adding a runtime suppressor would duplicate enforcement; better to clarify doctrine.
- **Removing the modules without consumers.** Each one was built with intent, has tests, has doctrine. The fix is wiring, not deletion.
- **Forcing autonomous-loop integration.** The autonomous loop is its own substrate; it builds in parallel. Tier 1's prompt-block extension makes the modules visible to *any* session that composes identity — autonomous + interactive both. No need to invade the autonomous loop's own building.
